# Sleep Monitor

Личный дневник сна, пульса, активности и самочувствия.

Система работает так:

**Xiaomi Smart Band → приложение Sleep Monitor на Android → сервер Sleep Monitor → Obsidian.**

Она автоматически получает данные с браслета, сохраняет их и позволяет утром быстро проверить или дополнить запись за день.

## Что записывается

В дневной записи могут быть:

- продолжительность сна;
- средний пульс днём;
- средний пульс во время сна;
- количество шагов;
- количество пробуждений;
- «Как спалось?»;
- самочувствие;
- алкоголь;
- свободные заметки.

Данные от браслета приходят автоматически. Личные поля можно исправлять вручную.

Сервер может работать с SQLite или Obsidian. Выбор задаётся в `.env` через `STORAGE_SERVICE`.

## Как пользоваться каждый день

Обычно достаточно открыть веб-страницу Sleep Monitor и выбрать нужную дату.

В форме:

1. **Сон** — продолжительность сна.
2. **Как спалось?** — субъективная оценка сна от 0 до 9.
3. Пульс за день и во время сна.
4. Шаги за день.
5. **Самочувствие** — оценка от 0 до 10.
6. Алкоголь.
7. Заметки.

### Переход между датами

Вверху формы находится одна текущая дата.

- **Назад** — сохранить текущую запись и открыть предыдущий день.
- **Вперед** — сохранить текущую запись и открыть следующий день.
- **Сохранить** — сохранить текущую запись и остаться на ней.

То есть при переходе на другой день отдельно нажимать «Сохранить» не нужно.

### Важная защита от потери автоматических данных

Если страница была открыта некоторое время, а за это время телефон успел прислать новые шаги или пульс, переход по дате не должен затереть эти более свежие значения.

При сохранении система сравнивает поля с тем, что было показано при открытии страницы:

- если поле **не менялось вручную**, сохраняется актуальное значение из выбранного backend-хранилища;
- если поле **изменили на форме**, сохраняется введённое значение.

Это особенно важно для полей, которые одновременно заполняются автоматически с телефона.

## Android-приложение

Приложение работает в фоне и периодически синхронизирует данные с сервером. После перезагрузки телефона синхронизация также планируется заново.

Требуется Android **9 (API 28) или новее**.

Приложение использует защищённое Bluetooth-соединение с браслетом. Если Mi Fitness одновременно подключён к браслету, синхронизация Sleep Monitor может не пройти.

### Первоначальная настройка

В приложении указываются:

- основной адрес сервера;
- резервный адрес сервера;
- PIN приложения;
- MAC-адрес браслета;
- ключ Xiaomi для этого браслета.

PIN должен совпадать с PIN на сервере.

Xiaomi-ключ является секретом. Его нельзя публиковать, помещать в README или передавать посторонним.

### Если синхронизация временно не работает

Данные не должны пропадать из-за кратковременной недоступности сервера.

Приложение сначала сохраняет полученные данные в собственной очереди, затем пытается отправить их на сервер. После успешной обработки сервером выполняется отдельное подтверждение получения данных от браслета.

Если сервер или подтверждение недоступны, очередь сохраняется и будет обработана при следующей попытке.

## Как обновить приложение на телефоне

Если у вас есть рабочая копия проекта и настроены Android SDK и adb, обновление можно выполнить одним файлом.

Подключите телефон к компьютеру с разрешённой USB-отладкой и из каталога android_sync_app запустите:

    build-release-install.bat

Скрипт выполняет шаги строго по порядку:

1. собирает release APK;
2. проверяет его подпись;
3. устанавливает APK на подключённый телефон.

Если один шаг завершился ошибкой, следующие шаги не запускаются.

Готовый APK находится здесь:

    app/build/outputs/sleepmon/sleepmon.apk


## API

API используется приложением Android и веб-интерфейсом.

### Авторизация

- `POST /login` — вход по PIN. В ответ устанавливается сессионная cookie.
- `GET /logout` — завершение веб-сессии.

### Данные

- `POST /sync` — автоматическая синхронизация данных с Android. Принимает дату, сон, пульс, шаги и пробуждения. Сохраняет автоматические поля через выбранный `STORAGE_SERVICE` и не перезаписывает пользовательские поля.
- `POST /save` — сохранение данных веб-формы. Перед записью читает актуальную запись и сохраняет только поля, которые действительно изменились на форме.
- `POST /api/storage/sync` — ручная синхронизация backend-хранилищ за месяц. Требует веб-сессию. Параметр `month=YYYY-MM` позволяет указать месяц, `force=true` — повторить уже выполненную синхронизацию.

### Выбор backend

В `.env` задаётся:

    STORAGE_SERVICE=obsidian

или:

    STORAGE_SERVICE=sqlite

Именно выбранный сервис используется для `/save` и `/sync`. Второй сервис остаётся резервным и участвует в ежемесячной синхронизации.

Ежемесячная синхронизация выполняется автоматически 1-го числа и сверяет предыдущий месяц. Если запись есть только в одном хранилище, она копируется в другое. Если запись есть в обоих, приоритет имеет сервис, выбранный в `STORAGE_SERVICE`.

Для SQLite используется:

    SLEEPMON_SQLITE_PATH=/data/sleepmon.db

В Docker этот каталог сохраняется через volume, поэтому SQLite-база переживает пересоздание контейнера.

## Веб-приложение

Веб-страница Sleep Monitor защищена PIN-кодом.

После входа можно:

- просматривать дневные записи;
- исправлять значения;
- добавлять заметки;
- переходить между датами;
- сохранять изменения.

Автоматическая синхронизация не должна затирать пользовательские поля:

- «Как спалось?»;
- самочувствие;
- алкоголь;
- заметки.

При ручном изменении поля оно, наоборот, сохраняется как введённое пользователем.

## Где хранятся данные

Дневные записи находятся в Obsidian:

    55-sleepmon/<год>/<месяц>/<дата>.md

Например:

    55-sleepmon/2026/10/2026-10-02.md

Obsidian используется как одно из двух backend-хранилищ. Какое хранилище является активным для `/save` и `/sync`, задаётся через `STORAGE_SERVICE`.

## Если сервер не отвечает

Если веб-приложение не открывается или Android не может выполнить синхронизацию:

1. проверьте, что сервер запущен;
2. проверьте основной и резервный адрес сервера в приложении;
3. не удаляйте приложение сразу — локальная очередь Android нужна для повторной отправки;
4. после восстановления сервера выполните синхронизацию ещё раз;
5. убедитесь, что запись появилась в Obsidian.

Если проблема связана именно с браслетом:

1. убедитесь, что браслет заряжен;
2. проверьте Bluetooth и сопряжение;
3. временно закройте Mi Fitness, чтобы он не держал соединение с браслетом;
4. повторите синхронизацию.

Незащищённое Bluetooth-соединение не используется как запасной вариант.

## Что делать при подозрении на неправильные данные

### Неправильный сон

Проверьте продолжительность сна и сравните её с браслетом. Если значение было изменено вручную, сохраните его через форму.

### Неправильный пульс во сне

Сравните значение с данными браслета. Sleep Monitor использует данные пульса из ночного блока файла сна, когда они доступны.

### Неправильный пульс за день

Дневной пульс рассчитывается по истории минутных измерений, исключая период сна. Если данных для расчёта недостаточно, существующее значение не заменяется нулём.

### Неправильные шаги

Для итогового числа шагов используется дневная сводка браслета, когда она доступна.

## Приватность и безопасность

Sleep Monitor предназначен для личного использования.

Не публикуйте:

- Xiaomi auth key;
- PIN;
- ключ Obsidian Local REST API;
- файлы с паролями;
- резервные копии дневника, если не хотите раскрывать личные данные.

Сырые файлы активности Xiaomi не должны сохраняться приложением как диагностические дампы или выводиться в Logcat.

## Если нужно только пользоваться системой

Для обычной работы не требуется разбираться в Git, Docker или исходном коде.

Нужно только:

1. один раз настроить сервер;
2. установить и настроить Android-приложение;
3. утром открыть Sleep Monitor;
4. проверить запись;
5. при необходимости поправить её и нажать «Сохранить».

Подробное техническое состояние проекта и оставшиеся задачи хранятся отдельно в task.md.
