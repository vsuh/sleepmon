# AI_CONTEXT.md — контекст проекта Sleep Monitor

## Назначение

Sleep Monitor собирает показатели Xiaomi Smart Band через Android-приложение и Bluetooth Classic RFCOMM/SPP, отправляет их в FastAPI backend, а backend обновляет дневные заметки в Obsidian через Obsidian Local REST API.

Основной репозиторий: https://github.com/vsuh/sleepmon  
Ветка по умолчанию: `master`  
Локальный Obsidian vault пользователя: `D:\\Sync\\AI.obsdn`

## Архитектура

- **Android app** (`android_sync_app/`): Bluetooth Classic SPP к браслету Xiaomi, аутентификация, получение activity-файлов и daily summary, локальная persistent queue, отправка данных, ACK отдельным SPP-сеансом, история синхронизации и WorkManager для фоновых запусков.
- **Backend**: FastAPI endpoints `/login`, `/sync`, `/save`, `/logout`; запись данных через Obsidian Local REST API. `/sync` должен учитывать существующие пользовательские поля заметки и возвращать фактические итоговые значения после merge.
- **Web form**: ручное редактирование полей дня и навигация по датам.
- **Deployment**: Docker Compose для app, Obsidian и dbtool.
- **Probe**: `tools/xiaomi_cloud_probe/` — отдельный экспериментальный инструмент для проверки Xiaomi Cloud. Это отдельный путь от Android SPP, его результаты не следует смешивать с результатами Bluetooth-синхронизации.

Основные показатели: `sleep_hours`, пробуждения, `pulse_avg_day`, `pulse_avg_sleep`, `steps_total`; ручные поля `well_being`, `sleep_quality`, `alco` и заметки.

## Технические инварианты и известные нюансы

- `SyncQueue` — durable outbox; не очищать её до успешных server sync и ACK.
- История синхронизаций обновляется после полного успешного цикла, а не при одном лишь получении данных с браслета.
- Для `steps_total` authoritative-источник — daily summary v5, когда он доступен.
- Sleep summary type=16 может сообщать неверную длительность; ранее для сна применялось вычисление по timestamps bed/wake с fallback. При разборе сна выбирать основную длительную сессию, а не короткий фрагмент, но не менять parser без актуальных доказательств.
- HR для сна извлекается из HR-блока sleep-файла внутри интервала bed..wake; type=10 не использовать как источник sleep HR.
- `SyncScheduler` использует `ExistingPeriodicWorkPolicy.KEEP`, чтобы обычный старт процесса не сбрасывал часовой интервал.
- `WorkManagerDiagnostics` хранит фактические состояния Worker, включая STARTED и итоговые состояния, чтобы отличать отсутствие запуска от незавершённого запуска.
- Секреты release signing находятся вне Git в локальном `_secrets/sleepmon-apk/keystore.properties`; не менять это соглашение и не добавлять ключи в репозиторий.
- GitHub Actions/Releases не считались настроенными в последнем зафиксированном состоянии; не утверждать обратное без проверки.
